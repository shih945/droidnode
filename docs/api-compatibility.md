# API 版本兼容策略

> 定于 2026-11-12。后续所有改动都按这份约定执行。

## 0. 优先级顺序（最重要）

```
① 能在当前的 1.36.5 控制面上跑通、能测   ← 最高
② 写法贴合 1.29 schema（编译器只认这个）  ← 自然结果，不是额外负担
③ 跨版本兼容（1.29 / 1.30~1.35）        ← 最后统一验证，现在不投入
```

**"基线 1.29"不等于"只能在 1.29 上跑"。** 控制面是 1.36.5，我们的 agent 一直是用
1.29 schema 编译的，从多容器、探针、卷挂载、envFrom、SA token 到日志与 metrics，
**全部都是在 1.36.5 上验证通过的**。原因：

| 为什么不会挂 | 说明 |
|---|---|
| 只用长期稳定的 `core/v1` | `nodes` / `pods` / `pods/status` / `events` 的线上格式没变过 |
| 未知名段被忽略 | 1.36 返回的新字段 serde 直接丢掉，不会报错 |
| 我们从不读版本做分支 | 行为只由自身代码决定，不因集群版本改变 |
| kubelet HTTP 接口是自己实现的 | `/pods`、`/containerLogs`、`/metrics`、`/stats/summary` 与集群版本无关 |

唯一的硬约束：**不要使用 1.30+ 才新增的字段**——那在 1.29 的 schema 里根本不存在，
编译器会直接拒绝，属于自找麻烦。

## 1. 基线版本：Kubernetes v1.29

| 事实 | 说明 |
|---|---|
| 编译期 schema | `k8s-openapi = { version = "0.21", features = ["v1_29"] }` |
| 上游上限 | k8s-openapi 0.21.1 只提供到 `v1_29`，1.29 就是当前依赖栈能选的最新稳定版 |
| 上报版本 | `models::KUBELET_VERSION = "v1.29.0"`，`kubeletVersion` / `kubeProxyVersion` 都由它生成 |

**1.29 是刻意选的，不是遗留。** 换更高的 schema 需要同时升级 `k8s-openapi` 和 `kube`，
在那之前所有新代码都以 1.29 为准。

## 2. 规则（对**新**改动生效）

1. **只用 1.29 就存在的 API 与字段。** 写代码前先确认该字段在 1.29 的 schema 里；
   1.30+ 新增的字段（例如 Pod 的新 condition、resize 相关字段）一律不用。
2. **不假设集群版本。** 不读 `/version` 来决定行为（只用于日志/注解），
   不因为集群是 1.36 就启用新路径 —— 行为必须只由我们自己的代码决定。
3. **宽松解析，不 panic。** 反序列化外部数据时未知字段忽略、缺失字段给默认值，
   避免控制面升级后直接崩。
4. **版本字符串只有一个来源**：`models::KUBELET_VERSION`。禁止再出现字面量 `"v1.29.0"`。
5. **不用已废弃 API。** 例如 `extensions/v1beta1`、`policy/v1beta1` 这类早就删掉的组。

## 3. 已存在的代码

不强制回头改造。发现某处依赖了 1.29 之后的行为时，按普通 bug 处理，不必专项回补。

## 4. 兼容性测试（最后统一做）

**现在不投入。** 开发期只有一个目标：**在当前 1.36.5 上跑起来、能测**。
等全部功能收尾后，再统一跑一次跨版本测试，届时覆盖：

| 场景 | 期望 |
|---|---|
| 1.36.5（当前环境） | 开发期全程在这里验证，必须始终可用 |
| 1.29 控制面 | 基线版本，收尾时补测，要求全绿 |
| 1.30 ~ 1.35 | 主流程可用；新版本特有字段不呈现 |

如果某个新功能不小心依赖了 1.36 才有的行为，**以"能在 1.36.5 上跑通"为准先落地**，
在代码里留 `TODO(compat)` 注明，收尾时一起处理。

## 5. 当前状态

- `KUBELET_VERSION` 常量与启动版本比对（`check_cluster_version`）在真机验证
  （节点上报 `v1.29.0`，注解 `droidnode.io/cluster-version=v1.36.5+k3s1`）。
- 97 项能力已收尾：A16 CSR serving 证书、A1/A2/A3、D2/D3、F1/F2 等均在
  k3s 1.36.5 上验证；清单见 [gap-list-feasibility.md](gap-list-feasibility.md)。
- 开发期验证环境固定为：k3s **v1.36.5+k3s1** + OnePlus PGJM10（Android 14，
  `192.168.2.9`），APK `targetSdk 35`。无线调试端口会变，以 `adb devices` 为准；
  当前 USB 序列号 `SWLRGUAAKBEIDULZ`。
