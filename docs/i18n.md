# 国际化（i18n）

## 现状

| 部分 | 状态 |
|---|---|
| 布局里的静态文案（标题、按钮、标签、提示、选项） | ✅ 已全部抽到资源，中/英各一份 |
| 代码里拼出来的动态文案（状态行、toast、错误详情） | ✅ 191 条全部走 `Tr.s()` 查表，中/英各一份 |
| 设置页「语言」切换（跟随系统 / 简体中文 / English） | ✅ 立即生效，重启后保持 |

布局里 **0 处硬编码中文**（脚本校验），`ui/v2/` 里也 **0 处中文字面量**；
`values/` 与 `values-en/` 的 key 完全对齐。

## 文件

```
android/app/src/main/res/values/strings.xml       # 默认 = 简体中文
android/app/src/main/res/values-en/strings.xml    # English
```

key 按界面分组：`v2_node_01`…、`v2_settings_27`…、`sheet_pod_01`…，新增文案时沿用同前缀递增。
带品牌/技术含义、不需要翻译的文本（`DroidNode`、`● STOPPED`、`apiVersion: v1 …`）保留在布局里。

## 加一门语言

1. 复制 `values-en/` 为 `values-<语言标签>/`（如 `values-ja`）。
2. 翻译其中的值，**key 不要动**。
3. `LocalConfig` 里加一个常量（`LANGUAGE_JA = "ja"`），设置页加一个 RadioButton。

## 切换是怎么生效的

和「外观」共用一套机制：`BaseActivity.attachBaseContext` 里用
`createConfigurationContext` 覆盖 `Configuration` 的 locale（外观则覆盖 `uiMode`），
所以 minSdk 26 就能用，不依赖 AppCompat / `LocaleManager`（API 33+）。

- 偏好存在 SharedPreferences 的 `language` 键，空串 = 跟随系统（此时不覆盖 locale）。
- 设置页切换后 `recreate()` 自己；其它页面在 `onResume` 发现语言变了会自动重建。
- 应用默认资源是中文，所以「跟随系统」在英文系统上会落到 `values-en`，其它语言回落到中文。

> 注意：`attachBaseContext` 里创建的是 Activity 的配置上下文，`Application` 不会被重建；
> 如果后续在 Application 里放文案，需要同样处理（或改成读取 `LocalConfig` 后再取字符串）。

## 代码里的文案：`Tr.s()`

`ui/v2/` 里不再有中文字面量。所有动态文案（状态行、toast、断连诊断）都由
`Tr.s("中文格式串", args…)` 生成：

```kotlin
heroSub.text = when {
    !running -> Tr.s("前台服务未在运行")
    maintenance -> Tr.s("已运行 %1\$s · 维护中，不再接收新的 Pod", Ui.uptime(startTime))
    else -> Tr.s("已运行 %1\$s · %2\$s / %3\$s 个 Pod 就绪", Ui.uptime(startTime), ready, pods.size)
}
```

- 查表键是**中文格式串本身**（`Tr.kt` 里的 `MAP`），值在 `values` / `values-en` 的
  `kt_000`…`kt_191` 条目里。新增文案：加一条 `Tr.s("中文")` + 两个资源条目即可。
- `BaseActivity.onCreate` 里 `Tr.bind(this)`，拿到的是**带语言覆盖的 Activity 上下文**，
  所以切换语言后每条文案都跟着变；没绑定（极少见）时原样返回中文，不会崩。
- 模板里的 `${expr}` / `$ident` 会被转成 `%1$s` 这类位置占位符，Kotlin 里写 `$` 要转义成 `\$`。
