# DroidNode 控制台 · 交互原型

这是**只读原型**：不参与 APK 构建，不引入任何依赖，不改动 `android/`、`agent/` 或
任何现有文件。所有页面都是本地静态 HTML，双击即开。

> 已经按这份原型在 APK 里落了新的 `ui.v2` 页面（新增文件，旧页面未动），
> 实现说明、真机截图和切换入口的步骤见 [`docs/ANDROID-V2.md`](docs/ANDROID-V2.md)。

打开方式：

- 直接双击 `index.html`（file:// 即可，不需要本地服务器）。
- 或者任意静态服务器：`npx serve prototype`。
- 页面用 hash 路由，可以直接分享某一页：`index.html#pods`、`#images`、`#logs`、`#settings`。

数据是 2026-11-12 00:26 从真机 `com.droidnode` 0.1.0 上取的快照，整理后写进 `app.js`：

| 数据 | 来源 | 快照文件 |
|---|---|---|
| 节点名 / Pod 列表 / 容器与重启次数 | `GET https://127.0.0.1:10255/pods` | [`_reference/apk-baseline/current-ui/api-pods.json`](_reference/apk-baseline/current-ui/api-pods.json) |
| 镜像、层数、压缩与解包体积 | `GET /images` | [`api-images.json`](_reference/apk-baseline/current-ui/api-images.json) |
| 节点内存 / 磁盘 / 逐 Pod RSS | `GET /stats/summary` | [`api-stats-summary.json`](_reference/apk-baseline/current-ui/api-stats-summary.json) |
| 日志文本 | `LogBuffer` / `adb logcat` | [`state-logs-paused.png`](_reference/shots/state-logs-paused.png) |

原型不发送任何网络请求：维护模式、删除镜像、拉取进度、重启 agent 都是本地状态机。

## 方向

**页面类型**：移动端 App（开发者 / 运维工具）+ 右侧评审注释。整页布局是「顶部一行主标题 + 一行副标题，下方左交互、右说明」。

**一句话方向**：把手机上的一台集群节点做成一块**值守面板** —— 深色为午夜蓝底、钠灯琥珀，亮色为冷灰白底、松绿强调，
数字用等宽、正文用中文系统字体，状态永远「色点 + 文字」。

**签名元素**：一条**心跳线**。它出现在四个位置，音量依次降低：

1. 节点页顶部的实时波形（运行中绿色、已排空琥珀、停止红色）；
2. 每个分区标题左侧的小刻度；
3. 空状态里的一条平线带一个脉冲；
4. 镜像拉取进度条与「启动中」状态。

除这条线外没有第二个装饰母题：没有渐变光球、没有图标卡片墙、没有玻璃拟态。

**与现状最大的三个变化**：

| 现状 | 原型 | 原因 |
|---|---|---|
| 全站等宽字体，中英文用空格对齐 | 正文用系统中文无衬线，数字 / ID / 日志用等宽 | 等宽中文字宽不一致，`ready=true` 这类协议字段也直接给人看 |
| 系统 ActionBar + 深色正文 + 浅色按钮三套配色 | 一套深色 token，强调色只用于「健康 / 可点击」 | 浅色按钮在深色底上比内容更亮，注意力全在按钮上 |
| 三个页面各说各的（仪表盘读 `/pods`，PODS 页读日志） | 一份状态、五个视图 | 同一时刻两处显示的 Pod 数量可以不一样 |

## 屏幕地图

| 页面 | 目的 | 主要交互 |
|---|---|---|
| **节点** `#node` | 能不能接 Pod、还剩多少资源 | 复制节点名、维护中提示（只读，点进设置）、Pod 行点开详情 |
| **Pod** `#pods` | 跑了什么、哪个在反复重启 | 状态过滤、点行进详情、详情跳日志 |
| **镜像** `#images` | 磁盘被谁占了、删掉不用的 | 拉取（模拟进度）、镜像详情、删除二次确认 |
| **日志** `#logs` | 定位一次失败的完整过程 | 级别过滤、搜索、暂停、清空、按 Pod 过滤 |
| **设置** `#settings` | 一眼看清节点状态，再进到对应的那一页 | 状态摘要、重启/停止快捷键、五个纯标题入口、「关于」一行版本号（进许可页） |
| **设置 › 节点与网络** `#settings-node` | 这台手机以什么身份、从哪张网卡、用哪个镜像源接入 | 节点名、kubelet 端口、网卡、三个镜像源、日志级别、底部唯一提交点 |
| **设置 › 集群连接** `#settings-cluster` | 能不能连上控制面、以什么身份连 | 地址/身份/文件、连接测试、加入或更换控制面（进三级页） |
| **设置 › 运行时与维护** `#settings-runtime` | agent 活着吗、在不在接 Pod、要不要停 | 状态与上报（只读）、维护模式、重启/启动/停止 |
| **设置 › 电源与后台** `#settings-power` | 让 Android 不要掐掉 agent | 电池优化白名单、开机自启、锁屏保持在线 |
| **设置 › 应用与诊断** `#settings-app` | 界面偏好与排障导出 | 配色、语言、导出诊断 |
| **设置 › 开源许可** `#settings-licenses` | 随 APK 分发的三方组件、协议与源码 | 组件列表（名称 + 协议 · 仓库地址），点一行开浏览器；页脚一行说明 |
| **加入集群** `#join` | 用最小凭据把手机接进集群 | 三种方式（地址 + token / 文件 / 粘贴）、CA 自动获取、先验证再落盘、返回 |

弹层：Pod 详情、镜像详情、删除确认、拉取镜像。

加入集群是**三级页**：设置 → 集群连接 → 加入集群，返回键在 appbar 内，
页面本身不建贴顶 header —— appbar 永远在模拟状态栏（真机上由 `env(safe-area-inset-top)` 撑开）之下。

### 设置为什么拆五页

原来是一张 9 段、30 多个控件的长页，滚动 3–4 屏。拆分的四条依据：

| 依据 | 结论 |
|---|---|
| 使用频率 | 运行时（每天多次）／电源（装机时一次）／节点与连接（配置时一次）／应用（几乎不动）不在同一层 |
| 风险等级 | 改名会在集群里新建 Node、改端口可能失联、停止 agent 会让节点掉线——破坏性操作各自成页，页首给警告 |
| 任务闭包 | 每页只有一个提交点：节点页「保存并重启」、连接页「加入/更换」、运行时页即时生效 |
| 信息前置 | 当前值集中在首页状态卡（节点、控制面、运行状态），入口只留名字；细节留到各二级页 |

结果：首页 1 屏内（状态 + 5 个入口），最深 3 层（设置 → 集群连接 → 加入集群）。

### 配色：Light / Dark，设置内切换

配色由「设置 › 应用与诊断 › 外观」驱动（原型与 APK 一致），默认亮色，选择记在 `localStorage`；所有颜色都走 `:root` 的 token，
整套换配色不需要改任何组件。App 里的外观选项也叫 **亮色 / Light** 和 **深色 / Dark**（外加「跟随系统」）。

| 主题 | 页面底色 | 强调色 | 适合 |
|---|---|---|---|
| `paper` · Light（亮色） | 冷灰白 | 松绿 | 白天办公、投屏评审、和 k8s 控制台并排看 |
| `night` · Dark（深色） | 午夜蓝 | 钠灯琥珀 | 夜间值守、长时间亮屏 |

对比截图：`_reference/shots/state-join-token.png`（Dark）、`state-join-paper.png`（Light）、
`state-settings-paper.png`。

### 设置页信息架构

**原型与 APK 都已拆成「首页 + 五个二级页」**（APK 是单 Activity 内切页，返回键先回首页）。

旧单页（`SettingsActivity`，2026-11-14 结构）：

1. **控制面** — 状态、地址、身份、kubeconfig 文件、加入集群入口、连接测试
2. **节点** — 节点名、kubelet 端口、镜像源 ×3、生效值、日志级别，以及「保存并重启 agent」
3. **运行控制** — 当前状态、agent 上报、维护模式开关、重启 agent、停止 / 启动 agent
4. **电源与后台** — 电池优化白名单、开机自启、锁屏保持在线
5. **外观** — 跟随系统 / 亮色 / 深色
6. **语言** — 跟随系统 / 简体中文 / English
7. **诊断** — 导出诊断
8. **关于** — 版本、许可（原型里已挪到设置首页页尾）

维护模式 = **cordon + drain**：先 `spec.unschedulable=true`，再停止本机容器；
关闭后恢复调度并重建容器。agent 停止时开关禁用，只显示「启动 agent」。

「唤醒锁」不再单独展示：应用在前台时它必然被持有，用户看到的永远是「持有中」，
等于没有信息；它的实际效果由「锁屏保持在线」这个开关表达。

### 可以直接点的状态

- 维护模式开 → 节点页变「节点已排空」并出现「维护中 · 去设置」提示条，Pod 变「已排空」，再关掉恢复。
- 停止 agent → 顶部变「已停止」，设置页只保留「启动 agent」；再次启动后若仍在维护模式，容器保持排空。
- Pod 详情 → 查看日志：跳到日志页并只看这个 Pod 的日志（顶部出现 Pod 筛选项）。
- 镜像 → 使用中的镜像删除按钮禁用；未使用的镜像删除要二次确认，并写明释放多少空间。
- 拉取：输入 `nginx:1.27-alpine` → 进度条推进 → 完成后新镜像进入列表。
- 日志暂停 3 秒 → 底部出现「继续 · N 条新日志」。
- 设置里端口填 `80` → 输入框变红并就近提示「端口需为 1024 至 65535 之间的整数」。
- 节点卡片改任意字段 → 点「保存并重启 agent」→ 出现保存提示，agent 进入「启动中」再回到运行中。
- 外观：点「跟随系统 / 亮色 / 深色」→ 整套配色立即切换（顶部的评审切换器也能切）。
- 语言：点「跟随系统 / 简体中文 / English」→ 只切换选中态并提示；原型不重渲染文案，真实切换在 APK 里。
- 诊断「导出诊断」→ 原型只弹提示，实际 APK 调系统分享发送文本报告。
- 加入集群：选「地址 + token」直接点「加入」→ 卡片顶部红字提示缺 token；
  切到「导入 kubeconfig 文件」→「从文件选择」会填入一份样例并提示已读取；
  填齐后「加入」→ 验证约 1 秒 → 回到设置页，状态变「已加入」、身份显示 token / 客户端证书。

## 文件结构

```
prototype/
├── index.html                  外壳、图标 sprite、手机框
├── styles.css                  设计 token、组件、响应式（≤720px 退化为全屏 App）
├── app.js                      状态、渲染、交互、定时器（无依赖，原生 JS）
├── docs/
│   ├── ANDROID-V2.md           ui.v2 在 APK 里的落地说明与切换入口
│   └── FEATURES-current-apk.md 现有 APK 的逐页功能总结与问题清单
└── _reference/
    ├── shots/                  原型各状态的浏览器截图（CDP 驱动生成，可随时重跑）
    ├── apk-baseline/           真机取证：uiautomator 层级 + agent 接口原始响应
    │   └── current-ui/
    ├── drive.mjs               用 CDP 点按并截图的小脚本（需要本机 Chrome）
    └── probe-agent.mjs         通过 adb forward 只读拉取 agent 接口的脚本
```

`_reference` 里的小脚本需要本机 Chrome 与页面地址，分别通过 `CHROME_BIN` 环境变量和命令行参数
提供（默认取上一级的 `index.html`），不写死任何本机路径；它们只用于这次的取证，不是产品代码。
`shots/` 是生成物，脚本每次运行会覆盖同名文件。

## 已知取舍

- **单主题**：只做深色。现有 APK 也没有浅色主题，原型先不铺两套。
- **不接真实接口**：Pod 删除、文件选择器、导出诊断包只给提示，不真的执行。
- **示例数据量小**：4 个 Pod、5 个镜像。列表虚拟化、滚动性能、500 行日志的渲染开销都没测。
- **逐 Pod 资源是模拟值**：但 `/stats/summary` 里确实有 `rssBytes` 与 `usageCoreNanoSeconds`，
  接进界面不需要改 Rust。
- **字体**：用的是系统字体栈，没有打包 Web 字体；真机上会落在 HarmonyOS Sans / 苹方。
